# План: вычислительный алгоритм траекторий (SCARA и 6-осевой)

Цель: робот **обязан** приезжать в цель без столкновений (с самим собой, с окружением,
с другими роботами) с небольшим запасом; уметь показывать 1–3 оптимальных варианта.

## 0. Общий каркас (единый для обоих роботов)

1. **Модель столкновений** (kinematic proxies — быстрее физики):
   * каждое звено = капсула (ось A–B, радиус r + запас `clearance`, по умолчанию 20–30 мм);
   * инструмент/TCP = сфера/капсула; стол, пол, ангар, другие роботы — свои капсулы/боксы;
   * проверка = `DistanceSegmentSegment` (уже реализовано в `SixAxisController`), плюс
     скип соседних звеньев и совпадающих осей (Axis4==Axis5).
2. **Проверка позы** `PoseIsFree(q) -> bool` и **штраф близости**
   `Penetration(q) = Σ max(0, clearance − dist)`.
3. **Планировщик**:
   * быстрый слой — **RRT-Connect / Bi-RRT** в пространстве суставов (6D / 3D+Z),
     узлы проверяются `PoseIsFree`, шаг интегрирования ~5–10°;
   * сглаживание пути — short-cut (случайные пары точек → прямая проверка) + сплайн;
   * таймирование — трапеция скоростей по максимальным угловым скоростям суставов.
4. **Несколько вариантов** — 2–3 прогона RRT с разными seed/эвристиками
   (короткий путь / минимальный размах суставов / максимальный запас), затем
   ранжирование: длина, число смен знака скорости, минимальный запас.
5. **Деградация**: если путь не найден — вернуть «лучшую достижимую позу»
   (минимум `Penetration` + расстояние до цели), показать красным, не двигаться.

## 1. SCARA (проще: 2 вращательных + призма)

* Конфигурация q = (θ1, θ2, z). Аналитика уже есть (`SCARAController.SolvePlanar2R`).
* Планирование в плоскости: строим 2–4 кандидата позы цели (локоть «+»/«−»,
  z сверху/снизу), отбрасываем позы с коллизией; путь = дуга θ1 + дуга θ2 + z,
  проверяем промежуточные точки (10–20 сэмплов) на столкновение с полом/столом/другим роботом.
* z-ход уже ограничен геометрией (низ — до столешницы, верх — низ стержня не в корпусе).
* Если цель недостижима: подтягиваем проекцию к границе рабочей зоны (max reach).

## 2. Шестиосевой

* Конфигурация q = (θ1..θ6), FK — по осям DH (`RobotDH`), TCP — TCP-прокси
  в центре меша фланца (пивоты FBX кривые — уже компенсировано).
* Планирование:
  1. **Seed-поза**: аналитическая аппроксимация «плечо–локоть» (2R в плоскости руки)
     + выравнивание запястья по направлению на цель (J4 = roll, J5 = pitch, J6 = roll);
  2. локальная оптимизация (CCD/Levenberg, 30–60 итераций) под ограничениями
     `PoseIsFree` и мягким штрафом близости;
  3. если CCD застревает (типовой случай — «захочет ударить локтем») — перезапуск
     из альтернативных seed'ов: elbow-up / elbow-down, J1 ± 180°, «переворот» J5.
* Явно запрещаем подход «внешней стороной корпуса локтя к цели»: штраф за то, что
  проекция линии TCP→цель проходит через корпус Axis3_2 (запрет приближения
  звеньев 2–3 к точке цели ближе, чем длина инструмента + запас).
* Лимиты суставов — жёсткие, «антипереворот» J5/J6 — мягкий штраф за |Δq| от текущей позы.

## 4. Критерии готовности

* 20 случайных целей: 0 пересечений (запас ≥ 20 мм), время до цели ≤ 5 с, отклик ≤ 1 кадр на пересчёт;
* при недостижимой цели робот останавливается, не «застревает» и не бьётся о стол;
* в UI — до 3 вариантов траектории с их длиной/временем.
